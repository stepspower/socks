# SOCKS pre-release security audit — 2026-10-11

Scope: everything under `socks/`, `packaging/`, `.github/workflows/ci.yml`, `pyproject.toml`,
measured against PLAN.md §1–§6 and docs/SECURITY.md. Where a finding depends on
`tesla-fleet-api` 1.17.3 behaviour, that code was read in `.venv`. Nothing was run against
Bluetooth, the car or Tesla endpoints, and no key or token file was read.
Line numbers refer to the tree as it stood after the audit's own small fixes (see §4).

## 1. Executive summary

**Verdict: fix first.** No Critical or High findings. The basics hold up well: keys and tokens
are written atomically with mode 0600 in a 0700 directory, key-parse errors are not chained,
`Tokens` hides secrets from `repr`, the client secret is never stored, PKCE is S256 with an
86-character verifier, `state` is compared in constant time, all SQL uses parameters, TLS
verification is never turned off, there is no subprocess, eval or pickle code, and there is no
telemetry. Both tools report no issues (bandit at medium and above, ruff `S`), and pip-audit
found no known vulnerabilities.

Fix these two Medium items before the first public release. Both are small:

- **M1:** the OAuth redirect URI says `localhost`, but the listener binds only `127.0.0.1`. The
  documented fixed port 53682 makes it easy for another local user to wait on `[::1]:53682`
  and catch the authorization code.
- **M2:** periodic polling over Bluetooth wakes a sleeping car on every read. The interval has
  no lower limit and polling keeps running while the window sits in the tray. Left running,
  SOCKS can stop the car from ever sleeping. With the cloud preferred, it can run up large
  Fleet API bills (at 1 s, about $170 a day).

### Checked and found sound

- **Keys:** P-256 checked on load. Group/other-readable files refused (`keys.py:86`). Parse errors use `from None` (`keys.py:99`). Temp file is `O_EXCL|O_NOFOLLOW` 0600 then `os.replace` (`keys.py:144-157`). The private key is never put in Settings, QSettings, the DB, logs or exceptions; the GUI handles keys by path only.
- **OAuth:** verifier `token_urlsafe(64)` (86 characters) with S256 (`oauth.py:229-237`). State is 256-bit and compared with `secrets.compare_digest` (`:326`). One-shot server: port 0, 300 s timeout, closed in `finally`, `access_log=None`. Response pages are fixed strings (no reflection) with `no-store` and `no-referrer`. No redirect is followed from the callback. Token errors are truncated server `error`/`error_description` only (`:373-379`). The client secret comes from getpass or an env var, never argv (`fleet/cli.py:51-59`), and is never persisted. Token writes are atomic 0600 under a 0700 directory.
- **Command gate:** the Controls tab only emits `command_requested`. `MainWindow._on_command` is the single path, with `confirm()` always called and typed confirmation for `ALWAYS_DANGEROUS` as well as core's flag. The tray menu and shortcuts send no commands. The CLI refuses dangerous commands without `--yes` (exit 3). The challenge is the last word's first 3 letters, case-insensitive and whitespace-stripped (unl/fru/tru). A command is never failed over after a possibly-delivered send (`maybe_executed`).
- **Transport:** no `ssl=False` or `verify_ssl` anywhere. The only `http://` URL is the loopback redirect. `check_public_key` uses `allow_redirects=False` and caps the body at 16 KiB. Every backend call has an `asyncio.timeout`. BLE `keepalive_interval=None`. Cloud reads never wake the car. aiohttp sessions are closed in `close()`/`_with_session`.
- **SQL:** every statement in `history/` uses `?` placeholders. No identifiers or values are formatted into SQL.
- **Exec:** no `subprocess`, `os.system`, `eval`, `exec`, `pickle`, `yaml` or `shell=True`. `webbrowser.open` only receives a URL built from fixed https hosts plus `urlencode`. Temp directories use `tempfile.mkdtemp` (0700).
- **Privacy:** no telemetry and no update checks. Fake mode uses a temporary config directory, temporary `gui.ini` and temporary DB (`app.py:126-135`, `main_window.py:271-274`), and never touches BLE or the cloud. `--debug` only raises the `socks` logger; `tesla_fleet_api` debug logs (request bodies, response JSON) stay off because no handler is attached and `socks` does not propagate. No log statement formats a token, key or auth header.
- **Repo:** `.gitignore` covers `*.pem`, `*token*.json`, `*.sqlite*` and `.env*`. `git ls-files` shows no key, token or DB. Test keys are generated at runtime or are dummy strings.

## 4. Changes made by this audit

These are Low/Info items, one line each and behaviour-neutral. Each is logged in
docs/DECISIONS.md with the `AUDIT:` prefix.

- `socks/core/model.py:81`: `raw` gets `repr=False` (I1).
- `socks/gui/tabs/status.py:34`, `socks/gui/tabs/controls.py:57`: `setTextFormat(PlainText)` (L8).
- `socks/gui/widgets/confirm_dialog.py:40-41`: refuse a dangerous dialog without a 3-letter challenge (I3).
- `packaging/flatpak/net.stepspower.Socks.yml`: removed the unused Notifications permission (I2).

M1, M2 and L1–L7 were **not** changed; they belong to the owning workers (FLEET: M1, L1, L4;
CORE: M2 backend/config, L2, L3, L5; GUI: M2 timer/spin box; PACKAGING: L6, L7).
